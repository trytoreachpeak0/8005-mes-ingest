# 一次性切换模式只自动删除已证明的旧库

用户要求门禁通过后由程序自动删除无备份旧库，但让常驻 Host 永久持有实例级删库权限会把运行缺陷扩大为不可恢复的数据破坏。决定自动删除只存在于由唯一 CutoverRunId 标识的一次性 MesIngestCutoverRun：它使用临时提升权限，旧 Host 停止后播种墓碑并验证新库；全部同窗门禁通过才删除显式旧库并结束，任一门禁失败则禁止删除、失败退出且不后台重试，正常 Host 账号从不拥有删库权限。

**Status**: accepted

**Consequences**:
- 删除目标必须同时满足：显式旧库名、不是系统库或新库、匹配预期旧 schema/contract、数据文件位于解析后的预期 SQL 数据目录、旧 Host 已停止且无业务连接、墓碑数量与哈希一致、全部门禁属于当前 CutoverRunId；不允许通配、名称前缀或自动猜测目标。
- 删除前必须在数据库外生成不可覆盖的 JSON/Markdown 证据并写 Windows 事件日志，记录实例、旧/新库身份、HistoryEpoch、版本、墓碑证明、三轮投影、接口检查、执行账号与时间；这些证据不包含业务原文，也不构成数据库备份。
- 临时提升权限在 MesIngestCutoverRun 结束后撤销；删除失败时新旧库均保留供检查，只有操作员发起新的明确运行才能再次尝试。
