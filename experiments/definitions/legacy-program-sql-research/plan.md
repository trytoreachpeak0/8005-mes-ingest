# 旧程序 SQL 访问代码研究计划

## 目的

系统梳理 [`sources/legacy-program-sql/2026-07-16/`](../../../sources/legacy-program-sql/2026-07-16/)
中的旧程序 SQL，识别其业务意图、依赖对象、输入输出、写操作风险和与当前需求的
可复用关系；研究来源快照，不直接把旧 SQL 变成正式查询。

## 关联问题

- 旧程序曾如何判断装片、烘箱、焊线、氮气柜和引线框架任务。
- 哪些表、视图、状态字段或位置映射尚未由客户 IT 正式说明。
- 哪些代码包含 MES 写回，当前只读方案是否仍需要对应业务能力。
- 哪些只读片段可以转化为新的问题假设或客户确认清单。

## 明确不回答

- 静态分类不证明 SQL 正确、安全、低负载或仍适用于当前 MES。
- 不因旧文件名或注释就确认业务语义。
- 不执行、改写或模拟任何写操作。
- 不允许应用、runner 或工厂 bundle 直接加载来源目录。

## 输入

- `source-manifest.json` 与 `catalog.csv` 中的逐文件哈希和初步分类。
- 客户现行 MES 对象说明、旧程序负责人访谈和当前业务需求。
- 如需验证只读候选，另建独立实验查询和清单，不修改来源快照。

## 前置条件与批准

1. 静态研究无需数据库连接，但结论必须标为 `SOURCE_OBSERVED` 或 `INFERRED`。
2. 任何数据库验证都必须由客户 IT 批准对象、参数、执行窗口、超时和负载边界。
3. 含 `WRITE_OR_PROCEDURAL_RESEARCH_ONLY` 的文件不得进入执行审批；只能形成业务问题。
4. 需要复用的只读逻辑必须复制为新的研究查询，重新通过 SQL guard、契约评审和哈希。

## 步骤

1. 先校验来源文件与 `source-manifest.json` 的 SHA-256，禁止在原快照上编辑。
2. 按功能目录逐个登记：业务动作、参数、输出、表/视图、筛选状态、位置含义和未知项。
3. 对照 `catalog.csv` 复核静态分类；出现 DML、DDL、PL/SQL、事务控制或调用时标为禁止执行。
4. 将只读候选与当前四个正式 QUERY_ID 对比，区分重复能力、补充能力和已废弃能力。
5. 对无法从资料确认的字段或状态建立客户问题，不以代码行为替代客户确认。
6. 如确需数据库验证，建立新的实验目录和临时 query manifest，只包含一条批准的 SELECT/WITH。
7. 保存运行证据、结果哈希和结论；验证成功也不自动晋升正式查询。
8. 只有业务契约、客户批准、数据质量与负载均明确后，才新建正式 QUERY_ID。

## 通过标准

- 20 个 SQL 文件均有研究状态和责任结论，不遗漏写操作文件。
- 所有推断均能追溯到文件哈希、客户答复或工厂 evidence。
- 没有来源 SQL 被正式应用或通用 runner 直接执行。
- 新发现的接口需求、风险和待确认项已进入业务文档或后续实验。

## 输出

- SQL 研究登记表：路径、哈希、业务意图、对象、参数、输出、风险、证据等级和结论。
- 写操作能力清单及当前只读替代/放弃结论。
- 客户 IT 待确认问题清单。
- 经批准的后续只读实验计划；不存在批准时不生成执行 bundle。
