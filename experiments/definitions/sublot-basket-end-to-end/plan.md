# SUBLOT 权威花篮数端到端实验

## 目的

验证操作员输入的 SUBLOT 和任务冻结 PACKAGE，经 `SUBLOT_BOX_COUNT` 查询与容量对照后，能够得到可复算的 V1 权威花篮数；成功时一次分配并批量打开等量 Mock 仓位，失败时在任何开锁副作用之前报错停止。

## 关联问题

- `max_box_count` 的查询值能否正确关联到任务 SUBLOT。
- PACKAGE 精确/批准前缀规则能否得到唯一容量。
- 向上取整、零值、空值、超时和对照缺失如何处理。
- 计算结果能否冻结为不可修改的 `ExpectedBasketCount`，并与完整目标仓位数保持相等。

## 明确不回答

- 不追踪实体花篮条码。
- 不把查询结果解释成最低数量或可修改参考值。
- 不因计算失败取消运输任务，但必须阻止本次装载。
- 不修改 MES 或自动修正容量参考。

## 输入

- 已验证的运输任务样本：SUBLOT、PACKAGE、TASK_TYPE。
- `QUERY_ID: SUBLOT_BOX_COUNT` 的批准版本与绑定参数。
- 当前容量对照和已批准的匹配规则。
- Mock 仓位、SUBLOT 输入、批量开门和仓门反馈事件。

## 前置条件与客户批准

- 客户 IT 批准在测试 SUBLOT 集合上执行只读查询、执行窗口和最大请求次数。
- 测试 SUBLOT 由客户提供或从已批准 evidence 选择，不在文档中散布生产明细。
- 现场负责人确认花篮容量，以及计算失败时报错且不开门。
- runner 能记录每次查询和计算的关联 ID。

## 安全边界

- SUBLOT 只通过绑定变量传入，不拼接查询。
- 请求串行或按客户批准并发上限执行，超时默认 30 秒。
- 不查询无关字段，不写 MES。
- 料盒查询失败、无结果、零/负异常值、PACKAGE 未匹配或规则冲突时，均不得取消任务或静默给默认花篮数，并且不得分配仓位或发送 Mock 开锁指令。
- Mock 仓门流程不得驱动真实设备。

## 步骤

1. 创建 run，记录任务样本、查询哈希、容量表版本和批准信息。
2. 对每个测试 SUBLOT 执行绑定查询，记录 `max_box_count`、耗时、状态和错误类型。
3. 使用任务创建时冻结的 PACKAGE 匹配唯一容量；记录规则 ID。
4. 仅在料盒数为正整数且容量为正整数时计算 `ceil(max_box_count / capacity)`。
5. 覆盖整除、非整除、单篮、多篮、空结果、超时、PACKAGE 空值、未匹配、规则冲突和异常数值。
6. 对成功计算验证冻结的 `ExpectedBasketCount` 不可修改，且一次分配的完整目标仓位数与之相等。
7. 用 Mock 验证系统一次发起完整目标仓位集合的批量开锁，并保留逐仓反馈；花篮放入顺序不产生身份或序号。
8. 对失败场景验证给出可诊断错误，且仓位分配数和 Mock 开锁指令数均为零。
9. 输出逐案例证据和汇总结论。

## 通过标准

- 所有成功案例计算可复算，使用正确 SUBLOT、冻结 PACKAGE、容量规则和向上取整。
- 所有失败/未知案例均 fail-closed，不取消任务、不伪造默认数量、不分配仓位且不发送开锁指令。
- 所有成功案例满足 `ExpectedBasketCount == target_slots.Count`，并一次发起完整目标仓位集合的批量开锁。
- 操作员和车载端均不能修改 `ExpectedBasketCount`，也不能通过重复输入 SUBLOT 追加花篮。
- 每条 SUBLOT—仓位占用及其时间段可追溯到任务与操作员会话；不生成花篮序号。
- 无 MES 写操作或真实设备副作用。

## 输出

- 逐 SUBLOT 查询与计算记录
- 成功/异常案例矩阵
- Mock SUBLOT 输入、完整仓位分配、批量开门与逐仓反馈日志
- 权威数量冻结与防修改验证报告
- manifest、原始输出和 SHA-256
