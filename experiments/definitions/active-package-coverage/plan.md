# 活跃 PACKAGE 覆盖率实验

## 目的

使用一个或多个已验证的 `MES_TASK_UNION` 活跃快照，评估当前观察到的 PACKAGE 对花篮容量对照表的命中率，识别高频未覆盖项。

## 关联问题

- 活跃运输候选中有多少 PACKAGE 可以精确匹配容量规则。
- 未匹配项是缺表、空值、拼写差异还是需要前缀规则。
- 未覆盖项会阻断多少次 V1 权威花篮数计算与批量开门。

## 明确不回答

- 不回答工厂 PACKAGE 全集是什么。
- 不把活跃样本称为“全量”“全集”或“完整覆盖”。
- 不自动新增、合并或修改容量规则。
- 不证明未在观察窗口出现的 PACKAGE 已停用。

## 输入

- 由 `import-run` 晋升的 `samples/mes-task-union/latest.csv` 与 `latest.meta.json`。
- 当前 [`package-basket-capacity.csv`](../../../reference/package-basket-capacity.csv)。
- 可选的多个已验证 run，用于降低单时点偏差。

## 前置条件与客户批准

- 输入 run 已通过 7 字段契约校验，PACKAGE 列存在。
- 客户 IT 批准使用相应生产快照作离线分析；若需重新查询，须批准对象、时间和负载。
- 业务负责人确认容量表版本和精确匹配/前缀匹配规则。

## 安全边界

- 优先离线分析已导入样本，不为提高覆盖率擅自查询生产 MES。
- 不包含真实连接信息或操作员隐私。
- 空 PACKAGE 单独统计，不用空字符串或默认值伪造匹配。
- 任何模糊匹配只生成候选，不直接进入正式参考表。

## 步骤

1. 记录 `run_id`、sourceEvidence、样本哈希和容量表版本。
2. 按原始 PACKAGE 值统计行数和去重值，不先改大小写或删内部空格。
3. 执行精确匹配，统计命中行数、命中唯一值数和按任务类型的命中率。
4. 将空值、未匹配值、仅首尾空格差异、大小写差异、疑似前缀匹配分别列出。
5. 对未匹配项按活跃行数和任务类型影响排序。
6. 对 `TOLL-` 候选只引用 toll-prefix-boundary 的已批准结论，不在本实验自行扩大边界。
7. 多 run 情况下分别报告每个窗口，另给并集；不得把并集称为工厂全集。
8. 输出建议补表清单，等待业务负责人审核。

## 通过标准

- 每个百分比均可追溯到输入 run、哈希、分母和容量表版本。
- 精确匹配、空值、未匹配和候选前缀匹配之和与输入行数一致。
- 报告显著标明“活跃观察覆盖率，不是 PACKAGE 全集覆盖率”。
- 未经批准不修改正式容量参考。

## 输出

- 覆盖率摘要
- 按任务类型统计
- PACKAGE 去重值与频次
- 未覆盖项及影响排序
- 候选容量规则评审清单
- manifest、日志和 SHA-256
