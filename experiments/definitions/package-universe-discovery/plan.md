# PACKAGE 候选全集发现实验

## 目的

在客户 IT 明确批准的 MES 对象、历史时间范围和负载边界内，发现 PACKAGE 候选集合，并量化此次发现的边界与未覆盖风险。

## 关联问题

- 哪个主数据或历史对象最接近有效 PACKAGE 的权威来源。
- 在批准时间范围内出现过哪些 PACKAGE，频次与最近出现时间如何。
- 活跃任务样本漏掉了哪些历史或低频 PACKAGE。

## 明确不回答

- 未经数据所有者确认，不宣称结果是工厂 PACKAGE 全集。
- 不证明某 PACKAGE 当前仍可生产或已停用。
- 不扫描未批准的表、视图、分区或无限历史范围。
- 不自行推断业务有效状态，不修改主数据。

## 输入

- 客户 IT 批准后新建的研究查询版本；批准前不存在正式 QUERY_ID 或可执行 SQL。
- 客户 IT 指定的查询对象、过滤字段、起止时间、最大返回行数和执行窗口。
- 可选的已验证活跃 PACKAGE 集合，用于差异分析。

## 前置条件与客户批准

执行前必须取得客户 IT 的明确批准，且 manifest 必须记录：

- 允许查询的数据库、Schema、表/视图和列。
- 时间范围及其业务含义。
- 预计扫描行数、返回行数上限、超时和执行计划评估。
- 允许执行的时段、并发限制、责任人和停止条件。
- 是否允许导出原始值，以及脱敏/保留期限。

缺少任一项时不得执行。活跃任务样本不能替代本批准，也不能作为“全集”输入。

## 安全边界

- 只执行批准的只读查询和绑定参数。
- 禁止无时间边界的历史扫描，除非客户 IT 对明确对象作出书面例外批准。
- 单次达到超时、行数上限或客户停止信号立即终止，不自动扩大范围重试。
- 不在业务高峰擅自运行，不并发分片提高吞吐。
- 输出仅保留 PACKAGE 及批准的聚合字段，不导出无关生产数据。

## 步骤

1. 在 manifest 固化批准对象、时间范围、负载上限、查询哈希和停止条件。
2. 先由客户 IT 评估执行计划或提供等价评估，不在生产库擅自运行可能写入的计划命令。
3. 运行最小批准窗口的试探查询，记录耗时、扫描/返回规模和数据库反馈。
4. 只有客户 IT 确认试探结果安全后，按批准范围运行正式发现。
5. 原样保存 PACKAGE，另生成仅用于分析的首尾空格、大小写和 Unicode 差异列。
6. 统计唯一值、频次、最早/最近出现时间和来源对象。
7. 与活跃样本、容量对照表比较，区分“历史出现”“当前活跃”“容量已覆盖”。
8. 将客户 IT/业务负责人确认的权威性结论写入日志；未确认时结果称“候选集合”。
9. 生成哈希和不可覆盖证据包。

## 通过标准

- 查询严格落在批准对象、时间和负载范围内。
- 无超时、数据库告警或未批准的数据导出。
- 每个结果都能追溯到查询版本、参数、时间范围和 run_id。
- 报告明确给出发现边界；只有数据所有者书面确认时才可使用“全集”表述。

## 输出

- PACKAGE 候选集合
- 频次及时间范围统计
- 与活跃样本、容量表的差异
- 客户 IT 批准与运行日志
- 查询和产物 SHA-256
- 未覆盖风险与后续确认清单
